# 稳定性与版本策略

## SemVer

`rosetta.Version` 遵循 [Semantic Versioning 2.0](https://semver.org/lang/zh-CN/)：

- **major**：破坏性变更。公开符号删除/改名、字段类型变更、默认行为变更（会让现有代码静默改变结果）。
- **minor**：向后兼容的新增。新字段、新选项、新哨兵、新事件类型。
- **patch**：向后兼容的缺陷修复。

## 什么算破坏性变更

以下都算，必须走 major：

- 删除或重命名导出的类型、函数、方法、常量、字段。
- 修改导出字段的类型或 JSON tag（影响序列化）。
- 让原本成功的请求开始失败（新增本地校验、收紧默认值）。
- 改变 `ChatResponse.Content`/`StopReason` 的既有映射语义。

以下不算：

- 新增导出符号或字段（包括给结构体加字段——但调用方用位置初始化时会受影响，因此本项目建议用字段名初始化）。
- 新增 `EventType`，且默认不改变既有事件序列（如 `EventUnknown` 需要显式开启）。
- 错误信息措辞调整（哨兵与 `errors.Is` 匹配关系不变）。

## 弃用流程

1. 在 godoc 中标注 `Deprecated:` 并给出替代方案。
2. 至少保留一个 minor 周期。
3. 下一个 major 才删除。

## 冻结范围

已冻结、不轻易扩展的契约：

- `Protocol` 的字符串值（用于日志与配置，改动会破坏下游匹配）。
- `ErrorCategory` 的既有取值语义。
- `Stream` 接口的方法集（新增方法会破坏第三方实现）。
